Jak funguje
Claude Code
Uvnitř je jen jazykový model — hloupá, ale mocná funkce z textu na text.
Veškerá akce a paměť se odehrává kolem něj, ne v něm.
Cíl: pochopit, proč nástroj, který „umí jen psát text", dokáže spouštět příkazy a editovat soubory.
01 · model
Model je bezstavová funkce
Představ si automat na text: vhodíš dovnitř blok textu, vypadne blok textu. Nic víc uvnitř není.
Mezi dvěma voláními si model nepamatuje vůbec nic. Každé volání začíná od nuly.
To je klíč k celému zbytku prezentace — „paměť" konverzace je iluze, kterou vytváří okolí.

03 · model
Text vzniká token po tokenu
Model nenapíše odpověď najednou. Předpovídá jeden token, přilepí ho na konec, přečte celý text znovu a předpoví další.
Tomu se říká autoregrese — „predict the next word, given the previous context".
Malá vnitřní smyčka „napiš → přečti vše → napiš dál". Je to předstupeň té velké smyčky na konci prezentace.

Proč stejný vstup nedá stejný výstup
Model nevydá jeden token, ale rozdělení pravděpodobností přes možné tokeny. Z něj se pak losuje.

06 · harness
Druhý tah: cache, ať neplatíš dvakrát
Když se posílá celá historie znovu, neplatí se pořád za totéž? Skoro ne — díky prompt cachingu.
Neměnný začátek promptu (systém, nástroje, starší zprávy) se uloží. Při dalším tahu se za něj neplatí plná cena, jen zlomek.
Proto je pokračování v konverzaci levné a rychlé, i když technicky posíláme historii pokaždé celou.

07 · harness
Když dojde místo: kompaktace
Kontext je konečný. Dlouhá práce ho postupně zaplní. Co pak?
Claude Code sleduje zaplnění a než narazí na tvrdý limit, spustí kompaktaci: starší část konverzace shrne a nahradí souhrnem. Zůstane záměr úkolu, klíčová rozhodnutí a stav souborů; zahodí se doslovné výstupy nástrojů a mezikroky.
s kompaktací
Okno se uvolní, session pokračuje dál. Dlouhé sezení zůstává naživu.
bez kompaktace
Okno se zaplní → tvrdý limit. API buď odmítne požadavek, nebo odpověď ořízne. Konverzace by se v určitém bodě prostě zasekla.
08 · harness
Od modelu k agentovi
model
Umí jen navrhnout text. Nemůže sám spustit příkaz ani sáhnout na soubor. Žije mimo svět.
harness = Claude Code
Program okolo modelu. To on skutečně jedná ve světě: spustí příkaz, čte a zapisuje soubory, volá model dokola.
Model je mozek bez rukou. Harness jsou ruce — a také ten, kdo modelu čte a podává práci.
09 · model harness
Nástroje — dohodnutý jazyk
Model neplácne do textu „spusť tohle" a harness to nevydoluje regexem. Model vydá strukturovaný požadavek na nástroj (tool_use) — přesný JSON podle předem daného schématu.
Harness ho rozpozná, nástroj provede a výsledek zabalí zpět jako tool_result do dalšího vstupu.
Model pak dostane zase celou historii — včetně toho, co nástroj vrátil — a rozhodne, co dál.
← model
{ type: "tool_use",
name: "run_command",
input: { cmd: "npm test" } }
→ harness provede, vrátí
{ type: "tool_result",
content: "12 passed" }
